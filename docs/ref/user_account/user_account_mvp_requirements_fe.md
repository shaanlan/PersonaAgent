## 一、背景与目标

### 1.1 现状

| 现状 | 位置 | 问题 |
|---|---|---|
| 无登录注册，`uid` 由前端本地生成（`mbti_uid`）并随交卷请求自报 | `stores/useTestStore.ts`、`stores/useThirdPersonStore.ts`、`utils/request.ts` | 身份可伪造，答卷无法归属到真实用户 |
| 报告通过自增 `report_id` 直接读取 | `pages/[lang]/report/[id].vue`、`pages/[lang]/third-person/report/[id].vue` | ID 可枚举，存在越权读取风险 |
| 分享链接即报告 URL | `components/ReportHero.vue`、`useShare` | 无访问凭证概念，无法区分本人、分享者、陌生人 |
| 答题可匿名完成 | `pages/[lang]/quiz.vue`、`pages/[lang]/third-person/quiz.vue` | 这是产品优势，必须保留 |

### 1.2 目标

1. 提供邮箱 + 密码的注册、登录、登出、自动刷新、查看/修改资料、修改密码。
2. 会话对用户透明：Access Token 短效、Refresh Token 长效，过期自动续期，不打断答题与阅读。
3. 匿名答题流程保持不变；登录后交卷自动归属当前账号。
4. 报告读取引入“本人登录态 **或** 匿名报告访问键（`report_key`）”两种访问方式，关闭 IDOR。
5. 分享报告时把访问键安全地交给接收者，同时不把密钥放进 query、日志或 Referer。
6. 6 种语言全量覆盖，账号页面不进入搜索引擎与 sitemap，不破坏现有内容页的预渲染与 SEO。
7. 不引入纯 SPA、不新增运行时内容 API、不改变职业/关系/博客的构建期数据流。

### 1.3 非目标

- 不做登录墙：阅读类型、职业、关系、博客，以及答题，均不强制登录。
- 不做邮箱验证、找回密码、第三方登录、手机号登录。
- 不做“我的报告”列表、跨设备会话管理、账号注销、数据导出、RBAC 后台（P1 已补充报告列表/设备管理）。
- 不在前端保存密码、JWT 密钥或任何服务端密钥。

## 二、范围

### 2.1 MVP 包含

| 模块 | 前端能力 |
|---|---|
| 注册 | 邮箱、密码、确认密码、可选昵称；注册成功自动登录 |
| 登录 | 邮箱 + 密码；统一错误提示；安全回跳 |
| 登出 | 调后端注销 Refresh Token，清理本地会话 |
| 会话 | Access Token + Refresh Token 持久化、自动刷新、单飞刷新、跨标签页同步 |
| 当前用户 | 启动时校验会话、Header 展示登录态 |
| 账号页 | 查看邮箱/注册时间、修改昵称、修改语言偏好、修改密码、登出 |
| 答题 | 匿名与登录均可交卷；登录态自动归属；交卷后保存 `report_key` |
| 报告访问 | 自动携带 `Authorization` / `X-Report-Key`；无权限时展示统一错误态 |
| 分享 | 自测报告分享链接携带 `#rk=` 访问键；接收者打开后自动保存并清理 URL |
| 历史兼容 | 兼容后端 30 天旧报告访问窗口；窗口结束后展示可理解的无权限提示 |
| 国际化 | 6 语言 UI 文案、错误文案、账号页、隐私政策与服务条款更新 |
| SEO/渲染 | 账号相关页 `ssr:false`、`noindex`、不进 sitemap；内容页策略不变 |
| 安全 | 不记录 token/密码/报告键；不把报告键放 query；XSS 防护；HTTPS 前提 |

### 2.2 MVP 不包含

- 邮箱验证、找回密码、修改邮箱。
- Google / Apple / 微信 / 手机号登录。
- 我的报告列表、报告删除、分享链接管理、`report_key` 轮换（P1 已实现报告列表/删除/认领）。
- 多设备会话列表与远程下线。
- 账号注销、数据导出、隐私合规自动化流程。
- 管理后台与角色权限。

## 三、用户场景

| 场景 | 入口 | 期望结果 |
|---|---|---|
| 匿名快速测试 | `/{lang}/quiz` | 不登录也能完成并查看报告；本机保存报告访问键 |
| 答题后注册 | 报告页/Header 登录入口 | 注册成功自动登录，可回到原页面；已有匿名报告仍可访问 |
| 登录后测试 | `/{lang}/quiz` | 新报告归属当前账号；本人以后无需访问键即可查看 |
| 查看分享报告 | 好友发来的报告链接 | 链接携带 `#rk=`，打开即可看；无需注册 |
| 账号设置 | `/{lang}/account` | 修改昵称、语言偏好、密码；退出登录 |
| 会话过期 | 任意需要登录的操作 | 自动刷新；刷新失败时清理登录态并给出登录引导，不白屏 |
| 无权限报告 | 责任链不满足 | 统一显示“报告不存在或无权访问”，不泄露报告是否存在 |
| 触发限流 | 连续登录/注册 | 展示本地化提示与倒计时，不自动重试 |
| 旧分享链接 | 后端兼容窗口内 | 仍可打开；窗口结束后展示可理解的无权限提示 |

## 四、功能需求

### 4.1 注册

**路由**：`/{lang}/register`（无前缀 `/register` 为 CSR 语言跳转存根）

**表单**

| 字段 | 必填 | 前端规则 |
|---|:---:|---|
| 邮箱 | 是 | 去首尾空格、转小写；合法邮箱，≤254 字符 |
| 密码 | 是 | 8~72 字节（按 UTF-8 字节计算）；不得与邮箱相同 |
| 确认密码 | 是 | 必须与密码一致；仅前端校验，不提交 |
| 昵称 | 否 | ≤50 字符；留空由后端取邮箱 @ 前部分 |
| 语言 | 否 | 默认当前路由 locale；随请求发送 |

**行为**

- 提交前做前端校验，字段级错误就地展示；提交中禁用按钮并显示 loading，防重复提交。
- 注册成功（后端自动登录）后保存会话并跳转：
  - 有合法 `redirect` 参数时回到该站内路径；
  - 否则进入 `/{lang}/account`。
- 409：邮箱已注册，提示“该邮箱已注册，请直接登录”，并提供登录链接。
- 429：展示限流提示与 `Retry-After` 倒计时。
- 页面展示“注册即表示同意服务条款与隐私政策”，链接到当前语言 `/terms`、`/privacy-policy`。
- MVP 不展示“忘记密码”死链接；如需帮助，引导到 `/contact`。
- 标签、`autocomplete`、错误 `aria-live` 等可访问性要求见 §5.3。

### 4.2 登录

**路由**：`/{lang}/login`

- 字段：邮箱、密码；支持显示/隐藏密码。
- 登录成功保存会话并跳转：
  - 合法 `redirect` 优先；
  - 否则进入 `/{lang}/account`。
- 失败统一提示“邮箱或密码错误”，不区分邮箱不存在与密码错误。
- 401（禁用账号）同样使用统一错误提示，避免账号枚举。
- 429 展示本地化限流提示与倒计时。
- 提供注册链接。
- 登录成功后不强制切换当前页面语言；语言偏好只写入账号资料。

### 4.3 登出

- 入口：Header 用户菜单、账号页。
- 请求体携带当前 Refresh Token；无论后端返回成功与否，前端都必须清理本地会话。
- 清理后：
  - 账号页 → 回到当前语言首页；
  - 其他页面 → 停留当前页并切换为未登录 UI。
- 登出只影响当前设备会话；不清理本机保存的报告访问键（报告键是报告访问凭证，不是登录态）。
- 账号页提供“清除本机报告访问权限”入口：清除后本人报告需重新登录，匿名/分享报告需重新打开分享链接；不影响服务器报告与其他设备。
- 多标签页同步：一个标签页登出后，其他标签页的登录态应同步清除。

### 4.4 会话与自动刷新

- Access Token 默认 15 分钟，Refresh Token 默认 30 天；前端以服务端 `expires_in` 为准。
- 页面启动时：
  - 有本地会话 → 校验/刷新并拉取当前用户；
  - 校验失败 → 清理会话，按未登录展示，不阻塞内容页渲染。
- 请求前若 Access Token 即将过期（建议阈值 60 秒），主动刷新。
- 收到 401 时：
  - 单飞刷新（同一时刻只发一个刷新请求），并发的失败请求排队等待；
  - 刷新成功后重放原请求一次；
  - 刷新失败 → 清理会话并通知 UI，不循环重试。
- 答题/交卷等匿名可用接口：即使刷新失败，也应降级为匿名请求继续完成交卷，不能因登录态失效丢失答案。
- 禁止在 Service Worker / 服务端渲染阶段读取或写入 token。
- 不打印 token、Authorization、Refresh Token、报告键到控制台。

### 4.5 当前用户与账号页

**路由**：`/{lang}/account`（需登录）

- 未登录访问时重定向到 `/{lang}/login?redirect=...`，`redirect` 必须是站内路径。
- 资料区：
  - 邮箱：只读，MVP 不支持修改。
  - 昵称：可编辑，≤50 字符；保存成功后更新 Header 显示名。
  - 语言偏好：6 语言下拉；保存到账号资料。**不强制切换当前页面 language**，页面语言仍由 URL 决定。
  - 注册时间：按当前 locale 格式化展示。
- 安全区：
  - 修改密码入口。
  - 登出入口。
- MVP 不展示“我的报告”“已登录设备”等未实现模块。
- 保存操作需有成功/失败反馈；失败保留用户输入。

### 4.6 修改密码

- 字段：当前密码、新密码、确认新密码。
- 新密码规则同注册；新密码不得与当前密码相同（前后端都校验）。
- 成功后：
  - 后端返回新 token 对，前端替换本地会话，保持当前设备登录；
  - 其他设备的 Refresh Token 失效；
  - 展示成功提示，不清空当前页面。
- 当前密码错误：字段级提示“当前密码错误”，不触发登出。
- 修改密码请求失败不应清理会话（除非返回 401 表示 Access Token 失效，此时走刷新流程）。

### 4.7 入口与导航

- Header：
  - 未登录：桌面端与移动端菜单显示“登录”。
  - 已登录：显示头像/昵称入口，菜单包含“账号设置”“退出登录”。
  - 未完成会话恢复时展示占位，不出现“先显示已登录再闪成未登录”的 hydration 冲突。
- Header 现有导航顺序与移动端下拉模式保持不变，不为账号功能改变整体布局。
- 账号入口使用当前 locale 路径。
- Footer 可选增加“账号/登录”链接；不得挤占现有法律与快速链接区域。
- 所有页面保持无横向滚动。

### 4.8 匿名答题与登录态答题

- 不强制登录，三档问卷、第三人测试、双人测试流程不变。
- 登录后交卷：请求携带 `Authorization`，后端从 token 取 `uid`。
- 前端不再生成本地伪 `uid`，不再读写 `mbti_uid`。
- 为兼容部署过渡期的旧后端，交卷请求体可继续保留 `uid` 字段，但固定发送 `0`，且前端不将其作为身份依据；后端上线后该字段视为废弃。
- 交卷响应新增 `report_key`（明文仅返回一次）：
  - 自测存为 `self` 作用域；
  - 第三人存为 `tp` 作用域；
  - 存储失败（隐私模式/配额）不得阻断跳转，但需在内存中保留本次 key 供当前分享使用。
- 交卷过程中 Access Token 过期：自动刷新后重试；刷新失败则降级匿名交卷。
- `from=dual`、`self_report` 等现有上下文参数必须保留。

### 4.9 报告归属与访问键

**访问规则（与后端一致）**

1. 登录用户是报告本人 → 允许。
2. 请求携带的 `report_key` 与报告匹配 → 允许（分享接收者）。
3. 历史匿名报告且在兼容窗口内 → 允许（后端判定）。
4. 其他 → `404`，前端展示统一无权限态。

> MVP 不支持把历史匿名报告“认领”到新注册账号：登录不会改变旧报告 `uid=0` 的归属。匿名用户只能依赖本机保存的 `report_key` 或后端历史兼容窗口；丢失 key 且窗口结束后无法找回。

**前端要求**

- 读报告时自动携带：
  - `Authorization: Bearer <access_token>`（有会话时）；
  - `X-Report-Key: <key>`（本机存有对应报告键时）。
- 报告键**只放请求头**，禁止放 query、路径、Referer 可见位置。
- 自测与第三人报告分别按作用域取键，互不混用。
- 404 时展示“报告不存在或无权访问”，提供：
  - 未登录：登录按钮（回跳当前报告 URL）；
  - 已登录或匿名：重新测试按钮；
  - 不展示报告是否存在、归属哪个账号等可探测信息。
- 历史报告没有 key 时仍尝试读取，由后端兼容窗口决定成功或 404。
- 双人测试/第三人对比读取自测报告时，复用同一套自动带键逻辑；自测报告不可访问时对比区继续静默隐藏，不阻断第三人报告主流程。

### 4.10 分享报告

- 自测报告现有分享能力（复制链接、Web Share、社交分享、海报）保留。
- 分享 URL 规则：
  - 有报告键：`/{lang}/report/{encodedId}#rk={report_key}`；
  - 无报告键（历史报告/存储失败）：保持普通 URL，但 UI 提示接收者可能无法访问。
- 报告键使用 URL fragment：
  - 不发送到服务端；
  - 不进入访问日志；
  - 不通过 Referer 泄露。
- 接收者打开带 `#rk=` 的链接：
  1. 读取并校验格式；
  2. 保存到本机报告键存储；
  3. 用 `history.replaceState` 清理地址栏 fragment（保留 query）；
  4. 正常加载报告。
- 新 key 与本地旧 key 冲突时，以 URL fragment 中的新 key 为准。
- 第三人报告当前没有独立分享 UI，MVP 不新增；但报告页必须支持 `#rk=` 读取与清理，便于手动分享或后续扩展。
- 海报分享文本中的链接同样使用带 fragment 的分享 URL。
- 分享前不得把报告键写入页面可见文本、DOM 属性、埋点或错误日志。

### 4.11 历史报告兼容

- 后端提供 `legacy_report_cutoff`，默认建议 30 天窗口。
- 窗口内：旧匿名报告链接即使没有 key 也能打开。
- 窗口结束后：旧链接返回 404，前端展示统一无权限态，并引导重新测试或登录。
- 前端不硬编码截止日期，不自行判断历史兼容；完全以后端响应为准。
- 前端不得为了兼容而绕过 `X-Report-Key` 或关闭归属校验。

### 4.12 错误与限流

| 场景 | HTTP | 前端处理 |
|---|:---:|---|
| 参数错误 | 400 | 字段级提示；不展示后端原始 message |
| 未登录/凭证无效 | 401 | 需要登录的页面引导登录；匿名接口降级或展示无权限 |
| 邮箱已注册 | 409 | 提示并引导登录 |
| 报告不存在/无权 | 404 | 统一无权限态，不区分原因 |
| 触发限流 | 429 | 本地化提示 + `Retry-After` 倒计时，禁用提交直到冷却 |
| 服务端错误 | 5xx | 通用失败提示 + 手动重试 |
| 网络/超时 | — | 通用网络错误 + 手动重试；不自动循环重试 |
| 密码错误 | 401 | “邮箱或密码错误”；修改密码场景提示“当前密码错误” |

- 新 auth 接口错误信封为 `{code, message}`；旧报告接口为 `{error}`。前端统一归一化为 `{status, code, message}` 后再映射为 i18n 文案。
- 禁止把后端英文/中文原始错误直接展示给用户。
- 429 不自动重试；其他失败仅提供手动重试。

### 4.13 国际化

- UI 文案全部进入 `locales/*.json`，6 语言同步：`zh-CN`、`en`、`ja`、`ko`、`es`、`pt-BR`。
- 新增文案至少覆盖：登录、注册、账号设置、修改密码、Header 用户菜单、表单校验、错误/限流、无权限报告、分享提示。
- 日期、数字使用当前 locale 格式化。
- 隐私政策、服务条款需补充账号相关条款（邮箱、昵称、密码哈希、会话令牌、报告归属、数据保留），6 语言同步。
- 不做“仅中文/仅英文”的临时文案。

### 4.14 SEO、渲染与隐私

- 账号相关页面属于私有交互页，不是内容页：
  - `/{lang}/login`、`/{lang}/register`、`/{lang}/account` 使用客户端渲染（`ssr:false`）；
  - 输出 `noindex, nofollow`；
  - 不加入 `prerender:routes`，不加入 sitemap；
  - 设置 canonical 自身 URL（可选）与本地化 title/description，但不追求搜索收录。
- 无前缀 `/login`、`/register`、`/account` 为 CSR 语言跳转存根，不收录。
- 现有内容页（首页、类型、博客、职业、关系、静态页、双人落地页）预渲染策略不得改变。
- 登录/注册/账号页不放置广告位，避免干扰与合规风险。
- Header 引入账号入口后，首屏布局不得产生明显位移或横向滚动。
- 账号页不得使用 `v-html` 渲染用户昵称等输入内容。
- 不新增第三方脚本；GA4 事件不得包含邮箱、昵称、token、报告键。

## 五、非功能需求

### 5.1 安全

- 生产必须 HTTPS；后端同源反向代理，前端不新增 CORS。
- 不在 localStorage 之外额外存储密码、Refresh Token 明文副本或报告键索引。
- 不把任何 token 写入 URL（报告键是唯一例外，且必须在 fragment）。
- 不在日志、埋点、错误上报中输出 token、密码、报告键、Authorization 头。
- 昵称等用户输入按纯文本渲染；如未来允许 Markdown/HTML，必须走白名单清洗。
- 报告无权限统一 404 文案，避免通过不同提示探测报告或账号是否存在。
- localStorage 存储 token 属于 MVP 已知风险；上线前后端/部署侧应配置 CSP，P1 再评估 httpOnly Cookie 方案。

### 5.2 性能与稳定性

- 会话恢复不得阻塞首屏内容渲染；内容页仍可先展示 HTML。
- Header 的登录态展示使用客户端水合后的状态，避免 hydration mismatch。
- 自动刷新使用单飞，避免并发刷新触发后端重放检测。
- 不引入新的重型依赖；优先复用现有 `$fetch`、Pinia、Tailwind。
- 网络失败不能导致答题答案丢失；交卷失败保留当前答案并允许重试。

### 5.3 可访问性

- 所有输入有可见 `<label>`，错误通过 `aria-describedby` / `aria-invalid` 关联。
- 提交按钮 loading 时 `aria-busy`，并保持可用键盘操作。
- 表单错误使用 `role="alert"` 或 `aria-live="polite"`。
- 密码显示/隐藏按钮有明确 `aria-label`。
- 用户菜单支持键盘打开、Escape 关闭、点击外部关闭。
- 移动端触控目标不小于现有 Header 按钮尺寸。

### 5.4 兼容性

- 支持现有目标浏览器（移动端 Safari/Chrome、桌面 Chrome/Safari/Firefox/Edge）。
- Web Share 不可用时回退复制链接；Clipboard API 不可用时回退 `execCommand`（复用 `useShare`）。
- 隐私模式/localStorage 不可写时，登录仍可在当前标签页内存中工作，但刷新后需重新登录；不得崩溃。

### 5.5 构建与发布

- `npm run build` 零错误是唯一自动化门禁。
- 新增路由必须在 `nuxt.config.ts` 明确渲染策略，并确认 sitemap 排除。
- 上线顺序必须与后端约定一致，避免旧前端读不出新归属报告。

## 六、验收标准

### 6.1 功能验收

1. 6 语言下均可完成注册、登录、登出、刷新、查看/修改资料、修改密码。
2. 注册成功自动登录；重复邮箱返回 409 且有登录引导。
3. 登录失败统一提示，不区分邮箱不存在与密码错误。
4. Access Token 过期后，任意 API 请求可自动刷新并成功重放；并发 401 只触发一次刷新。
5. 刷新失败时清理登录态，页面不白屏、不循环请求。
6. 未登录可完成自测、第三人测试、双人流程；登录后交卷归属当前账号。
7. 前端不再生成/读取 `mbti_uid`，交卷不再以请求体 `uid` 作为身份来源。
8. 匿名报告交卷后保存 `report_key`；带 key 可读，不带 key 且非本人为 404。
9. 登录本人报告无需 key 即可读取。
10. 分享链接使用 `#rk=`；接收者无账号也能打开；打开后地址栏 fragment 被清理。
11. 报告键不出现在 query、页面文本、埋点、控制台日志中。
12. 历史兼容窗口内旧链接可读；窗口结束后展示统一无权限态。
13. 第三人报告的自测对比在自测报告无权限时静默隐藏，不阻断主流程。
14. 429 展示倒计时并禁用提交；不自动重试。
15. 修改密码后当前设备保持登录，旧密码立即失效，其他设备 Refresh Token 失效。
16. 一个标签页登出后，其他标签页同步为未登录。
17. 账号页未登录访问会跳转登录，登录后回到账号页；`redirect` 不允许跳到站外。
18. 登录/注册/账号页不展示广告，无横向滚动。
19. 登出后本机报告访问键保留；账号页“清除本机报告访问权限”可清除，本人报告需重新登录，匿名/分享报告需重新打开链接。

### 6.2 国际化与 SEO 验收

1. 6 个 `locales/*.json` 均包含新增 key，无缺失回退到中文。
2. 隐私政策、服务条款 6 语言均已补充账号相关说明。
3. 账号页面返回 `noindex, nofollow`，不在 sitemap.xml 中。
4. 内容页仍预渲染，HTML 中有实质内容；账号功能未改变现有路由策略。
5. 语言切换不影响已登录状态。

## 七、上线顺序与回滚

### 7.1 上线顺序

1. 数据库迁移（低峰期，先备份）。
2. 后端发布，`auth.enforce_report_ownership=false`（仅过渡期），设置 `legacy_report_cutoff`。
3. 前端发布：登录/注册/账号页、会话自动刷新、交卷保存 key、报告带 token/key、分享带 fragment。
4. 验证新交卷报告均能按“本人 / key”访问后，将 `enforce_report_ownership` 恢复为 `true`。
5. 观察 30 天，再将 `legacy_report_cutoff` 设为过去时间并移除兼容逻辑。

### 7.2 回滚

- 前端回滚前，先把后端 `enforce_report_ownership` 置回 `false`；否则旧前端不带 key，匿名报告会读不出。
- 前端回滚不删除用户已保存的报告键；新版本恢复后再启用。
- 不删除 `users` / `refresh_tokens`，不影响新后端运行。
