# 一、产品背景与目标

本项目是一个以 MBTI 为核心的测试与内容型网站，目标用户包括：

- 想快速完成 MBTI 测试、查看结果的普通用户
- 想了解某个人格类型的读者
- 想从第三人视角评估伴侣、朋友、同事、上司的用户
- 想进行双人关系对比的用户
- 通过搜索进入职业、关系、性格内容的用户

产品目标：

1. 提供完整、顺滑的测评流程：答题 → 报告 → 类型解读 → 分享
2. 通过内容型页面获得搜索引擎流量
3. 满足广告联盟对内容充分性、页面结构和合规性的要求
4. 支持 6 种语言：`zh-CN`（默认/回退）、`en`、`ja`、`ko`、`es`、`pt-BR`
5. 在手机、平板、PC 上可用，禁止横向滚动
6. 支持深色 / 浅色 / 跟随系统主题

# 四、功能需求

## 4.1 自测

**需求**

- 支持三档问卷：简答、标准、完整。
- 逐题作答，点选选项后自动进入下一题。
- 支持返回上一题。
- 显示当前进度与总题数。
- 记录开始时间、结束时间与用户答案。
- 提交成功后进入独立报告页。

**验收**

- 三档问卷均可完成并拿到 `report_id`。
- 刷新答题页后，未提交的答案可恢复。
- 报告链接可独立打开，并兼容旧数字 ID。
- 答题页不能是无内容的纯交互空壳。

## 4.2 报告

**需求**

- 展示 MBTI 类型、类型昵称、特质标签。
- 展示总耗时、准确度、四维得分。
- 提供完整类型解读入口。
- 提供第三人测试入口。
- 支持下载海报、复制链接、重测。
- 从双人流程进入时，保留 `from=dual` 上下文。

**验收**

- 报告数据缺失/请求失败时有明确错误态。
- 海报可生成、预览、下载；移动端优先调用系统分享。
- 报告页不进 sitemap。

## 4.3 类型解读

**需求**

- 覆盖 16 型 × 6 语言。
- 内容包含：性格分析、优缺点、职业建议、关系、成长建议、名人案例、FAQ。
- 主内容使用 Markdown 渲染，支持标题、列表、引用、表格。
- 类型页需有 Hero、维度、分享卡片、相关内容和广告位。
- 页面标题、描述、canonical、hreflang、结构化数据完整。

**验收**

- `/{lang}/type/{type}` 可直接访问，6 语言均有内容。
- 无前缀 `/type/{type}` 正确跳转到语言版。
- 旧 `/result/{type}` 正确 301 到类型页。

## 4.4 第三人测试

**需求**

- 用户选择“我要测评谁”：伴侣、朋友、同事、上司。
- 按角色加载对应题目并提交。
- 报告展示推测类型、观察一致度、四维得分。
- 可读取用户自己的自测报告，展示“你与 Ta”对比。
- 可展示关系分析、关系探索入口、参考文献。
- 第三人报告不展示答题时长。

**验收**

- 四种角色均可完成测试。
- 没有自测报告时，对比区静默隐藏，不影响第三人报告主流程。
- 关系分析无内容时隐藏模块；网络失败时可重试。
- 报告页不进 sitemap。

## 4.5 双人测试

**需求**

- 有独立、可被搜索引擎收录的落地页。
- 明确展示三步流程：自测 → 测 Ta → 双人结果。
- 任一步未完成时，下一步不可进入。
- 结果页展示双方类型、四维对比、关系分析、关系探索入口。
- 复用已有自测/第三人报告，不新增双人后端 API。
- 第一步/第二步可从账号“我的报告”选择已有自测/第三人报告，无需重新测试。
- 报告选择器需登录，按步骤限定自测/第三人视角；未登录时展示登录引导。
- 不生成综合匹配度分数。

**验收**

- 6 语言落地页均可访问。
- 完成两步后可进入结果页；缺少任一步时有明确引导。
- 重置某一步后，该步完成态正确清除。
- 可从“我的报告”选择已有报告，选择后对应步骤完成态与结果类型更新；选择器不展示报告 ID。
- 结果页不进 sitemap。

## 4.6 职业探索

**需求**

- 提供职业索引页与详情页。
- 支持分类筛选、MBTI 类型筛选、搜索。
- 详情页包含职业概述、能力要求、MBTI 匹配、FAQ、相关内容。
- 匹配分数在内容构建期计算，前端不依赖运行时职业 API。
- 首页展示精选职业与“查看全部”入口。

**验收**

- 索引/详情页可预渲染，6 语言内容存在时进入 sitemap。
- 不存在内容的语言不生成空页面。

## 4.7 关系探索

**需求**

- 提供关系索引页、详情页、参考文献页。
- 覆盖 7 大分类：亲密关系、友谊、家庭、教育、照护、社交、职场。
- 详情页包含关系概述、相处建议、沟通模式、冲突、成长方向。
- 提供按 MBTI 类型查看的分型面板。
- 提供引用来源与相关关系入口。
- 数据由构建期 JSON 提供，无运行时关系 API。

**验收**

- 6 语言内容存在时预渲染并进入 sitemap。
- 参考文献页可搜索、筛选、查看引用。
- 缺内容的语言不生成空页面。

## 4.8 博客

**需求**

- 提供列表页与详情页，按语言前缀路由。
- 列表页支持分类筛选、计数、分页。
- 详情页支持 Markdown、目录、阅读时长、相关文章、类型自动内链、底部 CTA。
- 博客数据在构建期生成静态 JSON，无运行时博客 API。
- 相关文章由本地构建期数据匹配。

**验收**

- 6 语言博客列表与详情可预渲染。
- 旧无前缀 `/blog` 正确跳转到语言版。
- 文章内容不可依赖已停用的 `/api/blog`。

## 4.9 分享与海报

**需求**

- 优先使用 Web Share API。
- 不支持时复制链接，并提供社交平台分享入口。
- 报告海报为 960×1280，背景构建期生成，运行时只绘制百分比。
- 自测报告分享链接携带本机报告访问键，使用 URL fragment `#rk=`；无访问键时提示接收者可能无法访问。
- 接收者打开 `#rk=` 链接后自动保存访问键并清理地址栏 fragment。
- 第三人报告暂无独立分享 UI，但报告页支持 `#rk=` 读取。
- 类型页提供分享卡片。
- 私有原图只能通过加水印接口输出，不能直接下载。

**验收**

- 复制成功有明确反馈。
- 移动端支持带图分享时优先调用系统面板，否则下载图片。
- 海报生成失败时可回退为复制链接。
- 分享链接中的 `report_key` 不出现在 query，打开后 fragment 被清理。

## 4.10 静态页、广告与合规

**需求**

- 提供关于、联系、隐私政策、服务条款，6 语言覆盖。
- 广告只放在非首屏内容区块，不遮挡正文，不造成横向滚动。
- 默认只启用首页底部广告，其余通过白名单开启。
- 广告与统计脚本仅客户端加载。
- 不引入评论系统。

**验收**

- 广告联盟要求的页面均可访问。
- 关闭广告白名单后不展示广告位内容。
- 页面不存在横向滚动。

## 4.11 用户账号（MVP + P1 + P2）

**需求**

- 支持邮箱 + 密码注册、登录、登出、自动刷新会话。
- 注册字段：邮箱、密码、确认密码、可选昵称；前端校验密码 8~72 字节、确认一致，注册成功自动登录。
- 登录/注册受后端限流；触发 429 时展示本地化提示与 `Retry-After` 倒计时，不自动重试。
- 注册成功自动登录；登录失败统一提示，不区分邮箱不存在与密码错误。
- 提供账号页：查看邮箱/注册时间、修改昵称、语言偏好、修改密码、登出。
- 未登录访问账号页或我的报告页时跳转登录，`redirect` 仅允许站内路径。
- 账号页提供“清除本机报告访问权限”入口；登出保留本机报告访问键，不自动清除。
- 匿名用户仍可完成答题与查看报告；登录后交卷自动归属当前账号。
- 前端不再自报 `uid`；身份只来自 Access Token。
- 报告读取支持“本人登录”或“匿名报告访问键（`report_key`）”两种方式。
- 交卷后持久化 `report_key`；分享链接使用 URL fragment `#rk=`，不使用 query。
- 报告无权限时展示统一“不存在或无权访问”状态，不泄露报告是否存在。
- 后端历史报告兼容窗口内旧链接仍可访问；窗口结束后引导重测/登录。
- 6 语言覆盖登录、注册、账号页、错误与隐私政策/服务条款。
- 账号相关页面为 CSR，输出 `noindex`，不进入 sitemap；内容页预渲染策略不变。
- P1：提供 `/{lang}/account/reports` 我的报告列表，支持全部/自测/第三人筛选、游标分页、打开与软删除。
- P1：报告列表每页 20 条（后端上限 50），支持游标加载更多；报告项展示视角、类型、第三人角色、题量、用时、创建时间；结果不可用时展示不可用状态，不阻塞列表。
- P1：账号页展示最近 3 条报告摘要；报告删除后列表移除，读取统一 404。
- P1：登录/注册/会话恢复后凭本机 `report_key` 后台认领匿名报告；按报告去重、每批 20 条、同一时刻只执行一个认领任务，失败静默，不阻塞登录。
- P1：报告软删除幂等；已删除报告列表移除，本人 token 与 `report_key` 读取均 404。
- P1：账号页展示登录设备，最多最近 50 条并标识当前设备；支持撤销单设备、退出其他设备、撤销当前设备。
- P1：撤销当前设备后本地登出并跳转登录；其他设备 Refresh Token 立即失效，当前 Access Token 最长 15 分钟残留。
- P2：用户菜单提供与“账号设置”并列的“我的报告”入口，直达报告列表。
- P2：双人测试第一/第二步支持从“我的报告”选择已有报告；选择器按自测/第三人筛选，需登录；不展示报告 ID。

**验收**

- 6 语言均可完成注册/登录/登出/刷新/改密/改资料。
- Access Token 过期后自动单飞刷新；刷新失败清理会话且不循环请求。
- 未登录可答题；登录后报告归属正确。
- 匿名报告带 key 可读，不带 key 且非本人为 404。
- 分享链接在无登录态浏览器可打开；地址栏 fragment 打开后自动清理。
- 登出后本机报告访问键保留；账号页可手动清除，清除后本人报告需重新登录、匿名/分享报告需重新打开链接。
- 账号页不收录、不展示广告、无横向滚动。
- 修改密码后当前设备保持登录，其他设备 Refresh Token 失效。
- 登录/注册/报告列表/设备操作触发 429 时展示倒计时并禁用提交，不自动重试。
- 未登录访问账号页/我的报告会跳转登录，登录后回到原页面；站外 `redirect` 被拒绝。
- 报告列表 20 条/页，可筛选与加载更多；结果不可用报告不导致整个列表失败。
- 报告列表可筛选/分页；删除后列表不再出现，token/key 读取均为 404。
- 游客报告认领后进入列表；失败不阻塞登录。
- 设备列表能识别当前设备；撤销单设备/其他设备/当前设备行为符合后端契约。
- 账号子页 6 语言完整、noindex、不进 sitemap、无横向滚动。
- “我的报告”入口在桌面/移动用户菜单中可见；双人测试可选择已有报告并更新步骤完成态。
- 双人测试未登录点击“选择已有报告”时只展示登录引导，不请求报告列表；选择器不展示报告 ID。
- 后端迁移与 `enforce_report_ownership` 开关按上线顺序执行。

**非目标（MVP + P1 + P2）**

- 邮箱验证、找回密码、修改邮箱、第三方登录、账号注销/数据导出。
- 报告恢复/物理删除、`report_key` 轮换/吊销、报告重命名/收藏/标签。

**已知限制**

- 双人测试复用账号报告依赖登录态；退出登录后若本机无对应 `report_key`，双人结果可能无权限读取。
- 登录设备最多返回最近 50 条。
- 撤销当前设备后 Access Token 最长 15 分钟仍有效。
- 报告删除为软删除，数据保留，不支持恢复。

# 五、非功能需求

## 5.1 SEO

- 每个可索引页面必须有 `title`、`description`、Open Graph、canonical。
- 多语言页面输出 `hreflang`。
- 语义化标题：唯一 `h1`，按 `h2/h3` 递进。
- 博客列表 `ItemList`；博客详情 `Article + BreadcrumbList`；内容页按需输出 `FAQPage`、`HowTo`、`BreadcrumbList`。
- sitemap 覆盖 6 语言的内容页；报告页、结果页、重定向存根不进 sitemap。
- `robots.txt` 可访问。

## 5.2 渲染

- 内容型页面必须预渲染，HTML 中应有实质内容。
- 交互页可使用 SSR + 客户端水合或 CSR，但不能出现“纯 JS 空壳”。
- 禁止纯 SPA。
- 新增路由必须明确渲染策略，并同步 sitemap / prerender。

## 5.3 国际化

- 6 种语言全量覆盖 UI 文案与长内容。
- `zh-CN` 为默认与回退语言。
- 除中文首页 `/` 外，页面统一使用 `/{lang}/...`。
- locale 别名统一处理（如 `zh → zh-CN`、`pt → pt-BR`）。
- 面向用户的改动必须同步 6 个语言。

## 5.4 性能与可维护性

- 图片懒加载、使用 CDN/OSS。
- 构建期生成博客/职业/关系数据，减少运行时请求。
- 海报不依赖 DOM 截图库。
- 新增内容/路由时，构建必须零错误。
- 构建期生成物不提交到 git。

## 5.5 安全与隐私

- 密钥只放 `.env` 或服务端，只有 `NUXT_PUBLIC_*` 可进入浏览器。
- 不提交 `.env`、token、key。
- 报告 ID 使用非直接自增 ID 的编码形式。
- 账号会话只使用 Access/Refresh Token；前端不再生成或信任本地 `uid`。
- 报告访问键只放请求头与 URL fragment，不进入 query、日志或埋点。
- 第三方脚本仅客户端加载。
- 内容图片统一走 https CDN。

# 六、全局验收标准

发布前至少满足：

1. `npm run build` 或 `npm run generate` 零错误。
2. 关键路由冒烟通过：首页、quiz、报告、类型、第三人、双人、职业、关系、博客、登录、注册、账号、我的报告、静态页。
3. 6 语言内容页均无空白页/404。
4. 改动的路由已加入 prerender 与 sitemap（或明确排除）；账号页已 `noindex`。
5. 页面无横向滚动，广告不遮挡正文。
6. 关键页面有 canonical、description、Open Graph。
7. 未调用已停用或不存在的 API。
8. 未提交密钥、`.env`、构建期生成物。
9. 匿名与登录答题、报告访问键分享链路可用。
10. 报告列表/软删除/游客认领/登录设备链路可用。
11. 账号相关 429 限流提示与倒计时可用；双人测试可复用“我的报告”。
12. 账号页/我的报告未登录跳转与站内 `redirect` 校验可用。

# 七、发布与内容维护

- 内容源：`content/type`、`content/type-v3`、`content/career`、`content/relationship`、外部博客 Markdown。

  - 对应内容文件
