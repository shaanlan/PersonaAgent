# 一、背景与目标

## 1.1 现状

MBTI 独立网站已经具备完整的内容与测评能力：

| 能力 | 已有内容 | 用户入口 |
|---|---|---|
| 自测 | 10/20/40 题三档问卷、报告、分享 | `/{lang}/quiz` |
| 第三人测试 | 伴侣/朋友/同事/领导四种角色 | `/{lang}/third-person/quiz` |
| 双人测试 | 自测 + 测 Ta + 双人结果 | `/{lang}/dual-test` |
| 16 型详情 | 16 型 × 6 语言，性格、职业、关系、成长建议 | `/{lang}/type/{type}` |
| 职业探索 | 100 个职业 × 6 语言、匹配分数、FAQ | `/{lang}/career` |
| 关系探索 | 32 个关系主题 × 6 语言、7 大分类、引用溯源 | `/{lang}/relationship` |
| 博客 | 约 28 篇/语言 × 6 语言 | `/{lang}/blog` |
| 账号与报告 | 注册登录、我的报告、报告分享、登录设备 | `/{lang}/account`、`/{lang}/account/reports` |

现有内容足以回答大量用户问题，但用户需要自己找到正确页面：

- 不知道“我该做自测还是测别人”；
- 不知道“INFP 适合什么职业”应该去职业页还是博客；
- 搜索词与站内页面标题不一致；
- 关系、职业、类型内容分散在多个栏目；
- 用户拿到报告后，仍不知道下一步该做什么。

## 1.2 产品机会

在网站上增加一个**受控的 MBTI 对话助手**：

1. 用自然语言理解用户问题；
2. 基于站内真实内容回答，而不是自由发挥；
3. 把用户意图转成明确的站内动作：去自测、去测 Ta、去双人测试、看类型页、看职业页、看关系页、看博客；
4. 登录用户可在明确询问本人结果时，引用最近一次自测报告；
5. 对话可多轮、可流式展示、可保存历史。

该功能同时是 Agent 工程能力的展示载体：需要包含 Agent 工作流、状态、工具调用、RAG、路由、流式输出、评测、可观测性和降级策略，并保持代码可读、可学习。

## 1.3 产品目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 回答有依据 | 回答必须优先基于站内内容；无法确认时明确说明，不编造事实与链接 |
| G2 | 对话能落地 | 每次回答尽可能给出 1~2 个可点击的站内动作 |
| G3 | 体验自然 | 多轮上下文、SSE 流式、6 语言、移动端可用 |
| G4 | 身份可用但不强制 | 匿名可用；登录后可绑定会话、查看历史、按需引用本人报告 |
| G5 | 工程可展示 | Agent 工作流、RAG、工具、评测、日志、降级策略清晰可讲 |
| G6 | 保持精简 | 不做通用聊天机器人，不做开放式自主 Agent，不做多 Agent 协作 |

## 1.4 成功指标（MVP）

| 指标 | 目标 | 口径 |
|---|---|---|
| 意图路由准确率 | ≥ 90% | 50 条金标问题，人工标注 |
| RAG 召回率 Recall@5 | ≥ 85% | 金标问题对应正确页面/章节进入前 5 |
| 链接有效率 | 100% | 动作卡片链接全部来自站内路由白名单，打开不为 404 |
| 首字延迟 P95 | ≤ 5 秒 | 本地 3B 或远程模型，模型已预热；跨节点以实测为准 |
| 完整回答 P95 | ≤ 30 秒 | 典型 200~300 字回答，不含排队 |
| 对话错误率 | < 2% | 5xx/超时/流中断，不含用户主动取消 |
| 回答点赞率 | ≥ 70% | MVP 小样本；仅统计有反馈消息 |
| 降级可用率 | ≥ 95% | LLM 或检索失败时仍能给出可理解的引导 |

> 指标用于 MVP 验收与后续优化，不作为单次请求的硬 SLA。本地 CPU 推理与远程 API 的性能差异较大，部署时以实际压测为准。

## 1.5 非目标

- 不做通用聊天机器人，不回答与 MBTI、人格、关系、职业、本站使用无关的开放问题。
- 不做心理诊断、医疗建议、法律建议，不替代专业咨询。
- 不做联网搜索、实时新闻、外部网页抓取。
- 不做语音、图片、文件上传、多模态输入。
- 不做多 Agent 自主协作、长任务规划、代码执行、浏览器操作。
- 不做模型微调、训练、私有化模型评测平台。
- 不做对话分享、群聊、评论、社区。
- 不做后台运营管理界面（P1 可另立需求）。
- 不做对话内容的人工审核工作台。
- 不做跨站点、跨 App、原生客户端。
- 不改变现有内容页的预渲染、SEO、广告策略。

# 二、用户与核心场景

## 2.1 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 匿名访客 | 通过搜索或分享进入，不想注册 | 快速得到答案，知道下一步去哪 |
| 自测用户 | 刚完成或准备做测试 | 理解自己的类型、职业、关系建议 |
| 第三人测试用户 | 想评估伴侣、朋友、同事、领导 | 知道该用哪个测试、如何观察 |
| 双人关系用户 | 关心“我和 Ta 配不配” | 进入双人测试或关系探索 |
| 内容读者 | 搜索职业、关系、类型内容 | 找到对应文章/详情页 |
| 登录用户 | 有历史报告 | 结合本人结果获得个性化解释 |
| 求职/面试展示者 | 需要阅读和讲解 Agent 设计 | 看到清晰的工作流、工具、评测与工程取舍 |

## 2.2 核心场景

| 场景 | 入口 | 用户问题示例 | 期望结果 |
|---|---|---|---|
| 测自己 | 悬浮窗/聊天页 | “我真的是 INFP 吗？” | 解释判断依据 + 去自测按钮 |
| 测别人 | 悬浮窗/聊天页 | “怎么测我女朋友的 MBTI？” | 去第三人测试（伴侣）按钮 |

| 职业选择 | 职业页/聊天页 | “INFP 适合做什么职业？” | 职业建议 + 职业页按钮 |
| 关系建议 | 关系页/聊天页 | “哪些 MBTI 类型最适合做朋友？” | 关系建议 + 关系探索按钮 |

# 四、功能需求

## 4.1 对话入口与页面（FR-01）

### FR-01.1 悬浮窗

- 在公开内容页展示右下角悬浮按钮（桌面端圆形/胶囊，移动端适配安全区）。
- 点击后打开对话面板，不离开当前页面。
- 面板内展示：
  - 会话标题/欢迎语；
  - 推荐问题（按当前页面上下文生成）；
  - 消息流；
  - 输入框、发送/停止按钮；
  - “打开完整页面”入口；
  - 免责声明与隐私提示。
- 移动端面板为全屏或近全屏，禁止横向滚动。
- 以下页面默认隐藏悬浮窗，避免打断流程或泄露隐私：
  - `/{lang}/quiz`
  - `/{lang}/report/**`
  - `/{lang}/third-person/**`
  - `/{lang}/dual-test/result`
  - `/{lang}/account/**`
  - `/{lang}/login`、`/{lang}/register`
- 隐藏列表须可配置，不写死在组件中。

### FR-01.2 独立聊天页

- 新增 `/{lang}/chat`，支持直接访问、刷新、收藏、分享入口。
- 页面可展示历史会话列表（登录用户）和当前会话。
- 未登录用户也可以直接使用，历史仅保存在当前浏览器。
- 页面为私有交互页：
  - `noindex, nofollow`；
  - 不进入 sitemap；
  - 不预渲染；
  - 不加载广告。
- 无前缀 `/chat` 按现有语言规则跳转到 `/{lang}/chat`。

### FR-01.3 页面上下文

- 打开对话时，前端可传入当前页面上下文：路径、页面类型、slug、MBTI 类型（如适用）。
- 上下文只用于推荐问题和检索加权，不作为身份或权限依据。
- 服务端必须校验上下文路径在白名单内，忽略非法值。
- 示例：
  - 在 `/zh-CN/type/intj` 打开：推荐“INTJ 适合什么职业？”“INTJ 如何表达感情？”
  - 在 `/zh-CN/career` 打开：推荐“INFP 适合什么职业？”“职业匹配分怎么算？”

### FR-01.4 欢迎与免责声明

- 首次打开展示简短欢迎语和 3~4 个推荐问题。
- 必须展示“MBTI 是自我探索工具，不构成心理诊断或专业建议”的提示。
- 免责声明需 6 语言覆盖。

## 4.2 会话与历史（FR-02）

### FR-02.1 创建与恢复

- 首次发送消息时创建会话；也可在打开页面时预创建空会话。
- 服务端返回不透明 `session_id` 和仅返回一次的 `session_token`。
- 前端持久化 `session_id`、`session_token`、`locale`。
- 同一浏览器再次打开时恢复最近会话。
- 匿名会话通过 `session_token` 访问；登录用户通过登录态访问，也可继续使用原 token。

### FR-02.2 多轮上下文

- 服务端保存完整消息，生成回答时使用最近 N 条消息。
- 超过上下文预算时，使用滚动摘要压缩早期对话。
- 用户可在同一会话中追问，如“那 ENFP 呢？”“具体一点”。
- 上下文不得跨会话串用。

### FR-02.3 历史列表

- 登录用户可查看自己的会话列表：标题、最后消息摘要、更新时间。
- 支持打开、删除、清空（P1 可提供批量清空）。
- 匿名用户只能看到当前浏览器保存的会话；换设备/清缓存后不可恢复。
- 会话删除为软删除；删除后不可通过接口读取。

### FR-02.4 登录绑定

- 匿名会话在用户登录后，可绑定到当前账号，之后出现在“聊天历史”。
- 绑定必须由持有 `session_token` 或当前会话的同一浏览器发起，并通过 `POST /sessions/{id}:bind` 显式确认；不自动绑定。
- 已被其他账号绑定的会话不得被再次绑定。
- 退出登录后，历史列表不再展示该账号会话；本机已有会话仍可作为匿名会话继续使用（若 token 仍有效）。

### FR-02.5 数据保留

- MVP 默认保留 30 天；到期后会话与消息不可读。
- 保留期可配置。
- 用户删除会话后，消息立即不可读；物理清理由后台任务执行。
- 不持久化用户报告原文、密码、token、`report_key`。

## 4.3 回答质量（FR-03）

### FR-03.1 回答原则

- 优先基于检索到的站内内容回答。
- 回答结构建议：
  1. 直接结论（1~3 句）；
  2. 解释/依据（2~5 点）；
  3. 下一步动作（1~2 个）。
- 不编造站内不存在的页面、文章、职业、关系主题。
- 不把 MBTI 描述为绝对命运或科学定论；使用“倾向”“可能”“通常”等表述。
- 资料不足时明确说明，并给出澄清问题或站内入口。
- 涉及他人类型时，提醒“只能基于可观察行为推测，不能替代本人测试”。

### FR-03.2 来源展示

- 回答下方展示“参考来源”卡片，最多 3 条。
- 每条包含标题、栏目、可选章节、可点击的站内链接。
- 来源必须来自本次实际检索结果，不得由 LLM 生成。
- 无可靠来源时可不展示来源，但必须降低断言强度。

### FR-03.3 语言

- 回答语言与当前页面 locale 一致。
- 用户明确要求“用英文回答”时，可在当前会话内切换回答语言。
- 检索优先使用当前语言内容；不足时可使用中文内容作为依据，但回答仍使用用户语言。

### FR-03.4 长度与格式

- 默认 150~300 字（中文）或等价长度；用户要求“详细一点”时可扩展。
- 支持 Markdown 基础格式：段落、列表、加粗、链接（仅站内）。
- 不输出 HTML、脚本、iframe、外部图片。
- 不输出未经允许的外部 URL。

## 4.4 流式输出与交互（FR-04）

### FR-04.1 流式协议

- 使用 SSE（Server-Sent Events）。
- 事件类型：
  - `meta`：会话/消息 ID、请求 ID；
  - `sources`：参考来源；
  - `actions`：站内动作卡片；
  - `token`：增量文本；
  - `done`：完成、用量、结束原因；
  - `error`：错误码、可重试标记。
- 前端按事件渲染；收到 `done` 后结束 loading。
- 事件顺序与字段以 [design.md](design.md) §九为准。

### FR-04.2 停止生成

- 用户可点击“停止”中止生成。
- 中止后保留已生成内容，并标记消息状态为“已停止”。
- 中止请求必须释放模型资源，不得继续消耗 token。

### FR-04.3 重试

- 首 token 前发生网络错误：前端可自动重试 1 次。
- 已开始输出后出错：展示“生成中断，重试”按钮，不自动重试。
- 重试不得产生重复消息；使用 `client_message_id` 去重。

### FR-04.4 空状态与提示

- 加载中展示打字指示器/骨架。
- 模型排队时展示“正在准备回答”。
- 检索或模型降级时，不向用户暴露内部错误堆栈。
- 429 展示本地化限流提示与倒计时。

## 4.5 知识检索（FR-05）

### FR-05.1 覆盖范围

- 16 型详情页；
- 职业探索页；
- 关系探索页与引用；
- 博客文章；
- 站点静态页（关于、联系、隐私、条款中适合问答的部分）；
- 测试与页面路由元数据（问卷类型、角色、入口）。
- 不索引账号私有数据、报告内容、后台数据。

### FR-05.2 入库方式

- 离线采集与索引，不在运行时抓取页面。
- 支持从现有前端内容源（Markdown/JSON）构建。
- 索引构建可重复执行、可版本化、可回滚。
- 支持在 CI/Linux 预构建索引产物（Chroma + `catalog.json` + `index_manifest.json`）；跨节点部署时运行节点只加载索引产物，不访问主节点文章文件。
- 内容更新后需重新构建索引，构建失败不得影响线上旧索引。

### FR-05.3 检索要求

- 按语言过滤，优先当前 locale。
- 返回片段及其来源元数据（标题、栏目、路径、章节）。
- 对导航类问题（“INTJ 是什么类型”）优先走确定性页面查找，不依赖向量召回。
- 低置信度检索结果不得被当作事实来源。
- 检索失败时降级为“基于通用知识 + 明确说明”，并给出站内入口。

### FR-05.4 引用与时效

- 来源 URL 由服务端路由目录生成。
- 来源展示不要求模型逐句标注引用；但回答内容必须与来源相关。
- 内容更新时间可作为来源元数据展示（P1）。

## 4.6 意图识别与站内动作（FR-06）

### FR-06.1 意图

MVP 支持的意图：

| 意图 | 说明 | 典型问法 |
|---|---|---|
| `type_explore` | 了解某个 MBTI 类型 | “INTJ 是什么样的人？” |
| `self_assess` | 测自己/确认自己的类型 | “我真的是 INFP 吗？” |
| `assess_other` | 测别人/判断别人类型 | “怎么判断同事的 MBTI？” |
| `relationship_match` | 双人匹配/相处 | “我和他配吗？” |
| `career_fit` | 职业选择/职业匹配 | “ENFP 适合什么工作？” |
| `relationship_content` | 关系类型/相处建议 | “哪些类型适合做朋友？” |
| `mbti_concept` | MBTI 理论/测试原理 | “四个字母怎么来的？” |
| `personal_report` | 结合本人报告 | “根据我的报告我适合什么？” |
| `site_usage` | 站点使用/账号/报告 | “怎么保存测试结果？” |
| `small_talk` | 问候/感谢 | “你好”“谢谢” |
| `off_topic` | 与站点无关 | “帮我写代码” |
| `unsafe` | 诊断、医疗、歧视、自伤等 | “我是不是抑郁症？” |

### FR-06.2 路由规则

- 使用“规则预判 + LLM 结构化分类 + 结果校验”的混合方式。
- 输出必须包含：`intent`、`confidence`、`slots`、`search_query`、`need_personal_report`。
- 置信度低于阈值时：
  - 优先给出 2~3 个澄清选项；
  - 或给出通用回答 + 推荐入口；
  - 不得强行路由到错误页面。
- 类型槽位统一规范为 4 位大写字母（如 `INTJ`）。
- 关系角色统一为 `partner` / `friend` / `colleague` / `boss`。

### FR-06.3 动作卡片

- 每次回答最多 2 个动作，分主次。
- 动作类型：
  - `navigate`：打开站内页面；
  - `start_test`：开始自测/第三人/双人测试；
  - `open_report`：打开本人报告（仅登录且有权限）；
  - `open_history`：打开我的报告列表。
- 动作字段：类型、标题、描述、URL、图标/优先级。
- URL 必须来自服务端路由目录；LLM 不直接生成 URL。
- 动作点击应可埋点（不含 PII）。

### FR-06.4 典型路由

| 意图 | 主路由 |
|---|---|
| `type_explore` | `/{lang}/type/{type}` |
| `self_assess` | `/{lang}/quiz` |
| `assess_other` | `/{lang}/third-person/quiz` |
| `relationship_match` | `/{lang}/dual-test` |
| `career_fit` | `/{lang}/career`，可附具体职业详情 |
| `relationship_content` | `/{lang}/relationship` |
| `mbti_concept` | `/{lang}/blog`，可附具体文章 |
| `personal_report` | 本人报告页或 `/{lang}/account/reports`；无报告时 `/{lang}/quiz` |
| `site_usage` | `/{lang}/about`、`/{lang}/account` 或 `/report` 相关页 |
| `off_topic` | 无强制动作 |
| `unsafe` | 无商业动作，提供安全提示 |

## 4.7 本人报告上下文（FR-07）

### FR-07.1 使用条件

- 仅登录用户可用。
- 仅在用户明确询问与本人结果相关的问题时使用，例如：
  - “根据我的报告……”
  - “我最近一次测试结果是什么？”
  - “我适合什么职业？”（登录且已有报告时可询问是否结合）
- 默认不自动读取报告。
- MVP 只读取最近一次**自测**报告；第三人报告不纳入。
- 不读取其他用户报告；不读取已删除报告。

### FR-07.2 展示与隐私

- 使用报告时，在回答中显示轻量标识：“已结合你最近一次自测结果”。
- 不展示完整报告原文、答题明细、`report_id`、`report_key`。
- 不把报告内容写入 `chat_messages`；只记录 `personal_report_used=true`。
- 用户无报告或报告不可访问时：
  - 不报错；
  - 说明“还没有可用的自测结果”；
  - 给出开始自测按钮。
- 前端提供“本会话不使用我的报告”开关（P1 可持久化）。

### FR-07.3 权限边界

- 报告读取由现有后端完成；对话服务不得绕过报告归属校验。
- 用户 token 失效时不读取，不把错误详情暴露给用户。
- 账号注销、报告删除后，后续对话不再使用该报告。

## 4.8 反馈（FR-08，P1）

- 每条助手消息提供点赞/点踩。
- 点踩可选原因码：不准确、不相关、太笼统、链接错误、其他。
- 不收集自由文本，降低隐私与审核成本。
- 反馈数据用于离线评测与问题定位，不公开展示。
- 同一用户对同一消息可修改反馈，以最后一次为准。

## 4.9 安全与合规（FR-09）

### FR-09.1 内容安全

- 不提供心理诊断、疾病判断、用药建议、法律建议。
- 遇到自伤、自杀、暴力等高风险表达：
  - 不进行 MBTI 分析；
  - 给出简短安全提示，建议联系当地紧急服务或可信赖的人；
  - 不输出刺激性内容。
- 不生成针对性别、种族、地域、职业、年龄等的歧视性断言。
- 不把 MBTI 类型与智力、成功、道德水平直接挂钩。

### FR-09.2 提示注入

- 检索内容、用户输入、页面上下文均视为不可信数据。
- 系统提示明确要求忽略资料中的指令。
- 不向用户泄露系统提示、内部工具、模型配置、API 密钥。
- 不执行用户要求“忽略以上规则”“输出你的系统提示”等指令。
- 不调用除白名单以外的工具。

### FR-09.3 滥用与限流

- 匿名与登录用户均有限流。
- 限制单条输入长度、会话轮数、会话数量。
- 超限返回 `429` + `Retry-After`，前端展示倒计时。
- 对高频、重复、恶意请求可临时封禁 IP/会话（P1）。

### FR-09.4 隐私

- 不记录密码、token、`report_key`、完整报告内容。
- 日志默认不记录用户消息与模型回答原文；调试采样需脱敏并受开关控制。
- 对话数据保留 30 天，可配置；用户可删除会话。
- 第三方模型调用需明确数据使用政策；远程兜底仅在配置后启用。

## 4.10 降级与容错（FR-10）

| 故障 | 用户可见行为 | 系统行为 |
|---|---|---|
| LLM 超时/不可用 | 提示“回答服务暂时不可用”，给推荐入口 | 尝试远程 fallback；失败后返回模板回答 |
| 向量库不可用 | 给出站内入口与简短说明 | 跳过 RAG，不编造 |
| 检索无结果 | 说明“没有找到足够资料”，给澄清/入口 | 降低断言强度 |
| 报告接口不可用 | 不使用个人报告，继续通用回答 | 记录降级指标 |
| 流式连接中断 | 展示重试按钮 | 保留已生成内容，释放资源 |
| 数据库不可用 | 无法创建会话时返回明确错误 | 不进入 Agent，快速失败 |
| 队列已满 | 提示稍后重试 | 返回 429 或排队超时 |

## 4.11 可观测与评测（FR-11）

- 每次请求生成 `request_id`，贯穿日志、流事件、错误。
- 记录：意图、置信度、检索数量、最高分、模型、首字延迟、总耗时、token 用量、降级标记、错误码。
- 不记录用户消息原文（默认）；必要时仅记录长度与哈希。
- 提供离线评测脚本与金标问题集。
- 评测指标：意图准确率、Recall@5、链接有效率、语言正确率、引用相关性、平均延迟。
- 上线前必须跑通评测；指标下降需人工确认。

## 4.12 国际化（FR-12）

- 支持 `zh-CN`（默认/回退）、`en`、`ja`、`ko`、`es`、`pt-BR`。
- UI 文案、推荐问题、免责声明、错误提示、动作标题全部 6 语言覆盖。
- 回答语言与当前 locale 一致。
- 语言别名统一（`zh → zh-CN`、`pt → pt-BR`）。
- 来源标题使用对应语言内容；缺失时回退中文并标注。
- 日期/时间使用当前 locale 格式化。

## 4.13 渲染、SEO 与广告（FR-13）

- `/{lang}/chat` 为客户端交互页：
  - `ssr: false` 或 SSR 外壳 + 客户端水合；
  - `noindex, nofollow`；
  - 不进入 sitemap；
  - 不预渲染；
  - 不加载广告。
- 悬浮窗仅客户端加载，不影响内容页首屏 HTML 与 SEO。
- 悬浮窗不得造成明显布局位移（CLS）或横向滚动。
- 现有内容页的预渲染、canonical、hreflang、JSON-LD 策略不变。
- 对话页面不参与广告联盟内容页统计。

## 4.14 可访问性（FR-14）

- 所有按钮、输入框有可读标签。
- 支持键盘：打开/关闭、发送、停止、选择推荐问题、Escape 关闭。
- 消息流使用 `aria-live="polite"`，避免逐 token 打断屏幕阅读器（可节流到段落级）。
- 焦点管理：打开面板聚焦输入框；关闭后回到触发按钮。
- 颜色对比度符合 WCAG AA。
- 移动端触控目标不小于 44×44 px。

# 五、Agent 能力要求

MVP 必须包含以下 Agent 工程核心能力，并在代码与文档中可讲解：

| 能力 | 要求 |
|---|---|
| 状态（State） | 明确定义会话、意图、检索结果、动作、错误等状态字段 |
| 工作流（Graph） | 使用 LangGraph 组织节点与条件边，至少包含路由、检索、生成、收尾 |
| 工具（Tools） | 至少 3 个受控工具：内容检索、页面目录查找、本人报告读取 |
| 条件分支 | 按意图、置信度、是否需要个人报告、检索是否充分分支 |
| 循环/重试 | 检索不足时可改写查询重试，最多 2 次 |
| 流式 | token 级流式输出，支持取消 |
| 持久化 | 会话/消息落库，跨请求恢复上下文 |
| 评测 | 金标问题集 + 路由/召回指标 |
| 可观测 | 结构化日志、延迟、token、降级、错误码 |
| 安全 | Prompt 注入防护、工具白名单、URL 白名单、限流 |
| 可读性 | 模块边界清晰、类型完整、测试可运行、注释克制 |

> 具体节点、状态、工具契约见 [design.md](design.md) §五。

# 六、非功能需求

## 6.1 性能与容量

- 首字延迟 P95 ≤ 5 秒（3B 量化模型、模型预热、无排队）。
- 完整回答 P95 ≤ 30 秒（典型长度）。
- 单节点默认并发生成数 1~2；超出的请求排队或返回 429。
- 单会话最大上下文：最近 12 条消息或 3500 token，二者先到为准。
- 单条用户输入上限：2000 字符。
- 单条回答上限：600 token（可配置）。
- 会话列表分页，每页 20 条。
- 单用户最多 50 个活跃会话（可配置）。
- 对话服务故障不得影响现有测评、报告、内容页。

## 6.2 可用性

- 单节点/双节点部署目标月可用性 ≥ 99%（不含计划维护）。
- 模型/检索故障时降级可用率 ≥ 95%。
- 服务启动时完成数据库、向量库、模型配置自检；关键依赖不可用时 `/readyz` 返回 503。
- 优雅关闭：停止接收新请求，等待进行中的流结束或超时。

## 6.3 安全

- 全站 HTTPS；对话服务只通过内网/反向代理暴露。
- 生产密钥通过环境变量注入，不写入仓库。
- 与现有账号体系共用 JWT 密钥或通过后端校验 token；不信任前端自报身份。
- 主节点服务直连 Agent 时使用独立内部服务 token + 私网白名单，不复用用户 JWT、不下发浏览器。
- 会话 token 只存哈希；接口比较使用常量时间比较。
- 报告访问只通过现有后端，遵守 `report_key`/归属规则。
- 请求体大小限制、超时、限流、CORS 同源。
- 日志脱敏；不记录敏感头。
- 依赖供应链：锁定版本，定期扫描漏洞。

## 6.4 数据与隐私

- 数据最小化：只收集对话所需字段。
- 不存储报告原文、答题明细、密码、token、`report_key`。
- 会话默认保留 30 天；支持按会话删除。
- 提供数据删除说明；账号注销后的对话数据处理在 P1 明确。
- 第三方模型调用不发送不必要的个人数据；远程兜底需在隐私政策中说明。
- 对话内容不用于模型训练（除非另行取得同意）。

## 6.5 兼容性

- 前端：Vue 3 + Nuxt 3，复用现有 `$fetch`、Pinia、Tailwind、i18n。
- 浏览器：移动端 Safari/Chrome、桌面 Chrome/Safari/Firefox/Edge 最近两个大版本。
- 支持 POST + `fetch` 流式读取；不支持 SSE 原生 EventSource 的场景使用 fetch stream 解析。
- 反向代理需关闭缓冲，支持长连接。
- 移动端无横向滚动，适配安全区。
- 支持同阿里云同 VPC 的单机或双节点部署：双节点时 Nginx/Go/MySQL 在主节点，persona-chat/Chroma 在 Agent 节点；跨云/跨地域不在 MVP。
- 双节点不依赖主节点文章文件：索引离线构建，运行节点只加载索引产物。

## 6.6 可维护性

- Python 3.11+，全量类型标注；`ruff` + `mypy`（可选严格模式）。
- 分层：API → 应用服务 → Agent 图 → 工具/仓储 → 基础设施。
- Prompt、模型配置、路由目录版本化。
- 数据库迁移使用 Alembic。
- 单元测试覆盖核心路由、URL 构建、SSE 编码、会话权限、切分逻辑。
- 集成测试使用 mock LLM + 临时向量库。
- 关键设计决策写入本文档与 [design.md](design.md)。

## 6.7 成本

- 支持本地 CPU 推理与远程大模型两种模式；本地零 token 成本，远程按量计费。
- 远程模型设置月度预算与最大 token 限制。
- 限制上下文与输出长度，避免无界增长。
- 相同问题可做短期缓存（P1；需考虑个性化与隐私）。
- 监控每日请求量、平均 token、远程调用占比。

# 七、接口与数据需求（概要）

> 完整契约见 [design.md](design.md) §九、§十。

## 7.1 API 一览

Base：`/api/v1/chat`

| 方法 | 路径 | 认证 | 用途 |
|---|---|---|---|
| POST | `/sessions` | 可选 | 创建会话，返回 session_id/token/推荐问题 |
| GET | `/sessions` | 登录或会话 token | 会话列表（登录用户或当前匿名 token） |
| GET | `/sessions/{id}/messages` | 可选/会话 token | 会话详情与历史消息 |
| POST | `/sessions/{id}/messages:stream` | 可选/会话 token | 发送消息，返回 SSE 流 |
| POST | `/sessions/{id}/messages/{mid}:abort` | 可选/会话 token | 中止生成 |
| POST | `/sessions/{id}:bind` | 登录 + 会话 token | 登录后显式绑定匿名会话 |
| DELETE | `/sessions/{id}` | 可选/会话 token | 删除会话 |
| POST | `/messages/{id}/feedback` | 可选/会话 token | 点赞/点踩（P1） |
| GET | `/healthz` | 无 | 存活检查 |
| GET | `/readyz` | 无 | 就绪检查（DB/向量库/模型配置） |

认证方式：

- `Authorization: Bearer <access_token>`（可选）；
- `X-Chat-Session-Token: <session_token>`（匿名会话必需）；
- `X-Internal-Service-Token: <token>`（仅主节点内部服务直连，VPC 白名单，不下发浏览器）；
- 登录用户访问自己会话时可只用 Bearer。

## 7.2 SSE 事件

| 事件 | 用途 |
|---|---|
| `meta` | 会话/消息/请求 ID |
| `sources` | 参考来源列表 |
| `actions` | 站内动作卡片 |
| `token` | 增量文本 |
| `done` | 完成、用量、结束原因 |
| `error` | 错误码、可重试标记 |

## 7.3 数据实体

| 实体 | 用途 |
|---|---|
| `chat_sessions` | 会话元数据、归属、locale、标题、状态、摘要 |
| `chat_messages` | 消息、意图、动作、来源、模型、用量、状态 |
| `chat_feedback` | 点赞/点踩与原因码（P1） |

## 7.4 与现有系统的关系

- 账号与报告：复用现有 `PersonalityMatrix` 后端，不复制用户/报告表。
- 内容：离线读取现有前端内容源；不在运行时抓取内容页。
- 数据库：与现有 MySQL 同实例或同集群，使用独立表前缀 `chat_`；双节点时通过同 VPC 私网访问，不暴露公网。
- 部署：支持同机或同 VPC 双节点。双节点时主节点保留 Nginx/Go API/MySQL，Agent 节点运行 persona-chat/Chroma（Ollama 可选）；通过 Nginx 统一入口。
- 文件：运行节点不直接访问主节点 Markdown/JSON；索引在 CI/Linux 离线构建为 Chroma + catalog + manifest 后发布。

## 8.2 Agent 与 RAG 验收

- 50 条金标问题意图准确率 ≥ 90%。
- Recall@5 ≥ 85%。
- 动作链接 100% 来自白名单且可访问。
- 回答中不出现编造的外部 URL。
- 个人报告只在登录且明确询问时使用。
- 检索重试最多 2 次，不无限循环。
- 评测脚本可在本地与 CI 运行；结果可复现。
- 日志不包含消息原文、token、报告内容。

## 8.3 安全验收

- 提示注入样例（“忽略规则”“输出系统提示”“访问其他用户报告”）全部被拒绝或安全处理。
- 越权读取会话返回 404，不泄露存在性。
- 无效/过期 token 返回 401，前端可刷新后重试。
- 限流生效，429 带 `Retry-After`。
- 请求体超限、非法 JSON、超长消息均返回 4xx。
- 生产配置无明文密钥；仓库无 `.env`。
- 内部服务接口未携带正确 token 返回 401；内部 token 不进入浏览器。
- 远程模型兜底未配置时不会外发数据。

## 8.4 性能与发布验收

- 冷启动后完成模型预热；P95 首字/总耗时达标。
- Nginx SSE 不被缓冲；长连接 60 秒以上不被断开。
- 对话服务异常不影响现有首页、quiz、报告、类型、职业、关系、博客。
- `/{lang}/chat` 不出现在 sitemap；返回 `X-Robots-Tag: noindex, nofollow`。
- 内容页构建零错误；现有路由冒烟通过。
- 数据库迁移可重复执行，失败可回滚。
- 部署文档、配置说明、回滚步骤齐全。
- 同 VPC 双节点部署时：主节点 Nginx 可通过私网访问 Agent 的 8090，SSE 正常；Agent 可访问主节点 Go API 与 MySQL；运行节点不访问主节点文章文件。
- 索引产物包含 Chroma、`catalog.json`、`index_manifest.json`，可在新节点独立解压启动，并通过 `/readyz` 校验。
- 双节点回滚时只切回 Nginx 上游/停止 Agent，不影响主站、Go API 和 MySQL。

# 十、风险与待确认

## 10.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| CPU 推理慢 | 首字/总耗时超标 | 默认 3B 量化模型；限制输出长度；远程兜底；模型预热 |
| 小模型结构化输出不稳定 | 意图/JSON 解析失败 | 规则预判 + Pydantic 校验 + 重试 + 默认分支 |
| 检索跨语言效果不稳 | 6 语言回答质量不一致 | 多语言 Embedding；按语言过滤；中文兜底；评测集覆盖 6 语言 |
| 内容快照与线上不一致 | 回答引用过期内容 | 版本化快照；CI 构建；索引版本与内容版本绑定 |
| 提示注入 | 越权/泄露系统提示 | 数据/指令隔离；工具白名单；输出过滤；红队样例 |
| 个人报告隐私 | 用户信任风险 | 明确询问才读取；不落库原文；可见标识；可关闭 |
| 匿名滥用 | 资源耗尽/成本上升 | 限流、长度限制、并发控制、会话上限 |
| 范围蔓延 | 变成通用聊天 | 非目标写死；离题拒绝；评测约束 |
| 单节点可用性 | 服务中断 | 优雅降级；对话服务与主站隔离；优先双节点；快速回滚 |
| 双节点网络/授权 | Nginx、Go API 或 MySQL 跨节点不通 | 同 VPC 私网；安全组最小放行；上线前连通性检查 |
| 索引与 embedding 不一致 | 检索质量下降/不可用 | 索引 manifest 记录模型与维度；启动校验；换模型必须重建 |

## 10.2 待确认（含默认建议）
